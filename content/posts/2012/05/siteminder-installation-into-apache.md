We had a recent installation of Siteminder (Web Access management tool) into our systems and had to be configured into existing apache installation.<br/><br/>Here are some issues which came up and the tips which you could look into:<br/><br/><!--Ads1--><br/><br/><span>1. Did you give write permission to "site minder user"? for Apache Conf directory</span><br/><br/>(&lt;apache_root&gt;/apache/conf). Write permission for  "httpd.conf"  file as well.<br/><br/>2. Created directory "/opt/netegrity".<br/>Ideally this should be created in separate filesystem as a good practice.<br/>This would become much helpful for clustering and promotional model.<br/><br/>3. Add entries in the "load module section" within the Apache "httpd.conf"  file<br/><pre><br/> <em>LoadModule sm_module /opt/netegrity/webagent/bin/libmod_sm22.so</em><br/> <em>SmInitFile &lt;location of apache&gt;/conf/WebAgent.conf</em></pre><br/><pre>4. Manually add handlers<br/> <em># Manually added for siteminder </em><br/> <em># Add handlers</em><br/> <em># Siteminder .exe #</em><br/> <em>AddHandler cgi-script .exe</em><br/> <em># Siteminder .fcc</em><br/> <em>AddHandler smformsauth-handler .fcc</em><br/> <em># Siteminder .sfcc</em><br/> <em>AddHandler smsslformsauth-handler .sfcc</em><br/> <em># Siteminder .scc</em><br/> <em>AddHandler smadvancedauth-handler .scc</em><br/> <em># Siteminder .ccc</em><br/> <em>AddHandler smcookieprovider-handler .ccc</em></pre><br/>5. Did you add "Alias" entries from httpd.conf.<br/>Be careful the apache installation MAY NOT restart until unless you have the <strong>mod_alias</strong> installed<br/><br/>6. Add entry into  "&lt;apache_root&gt;/apache/bin/apachectl" file.<br/><pre># Entry made as per siteminder installation document<br/> <em>export EXTSHM=ON</em><br/> <em>[[ -r /opt/netegrity/webagent/nete_wa_env.sh ]] &amp;&amp; . /opt/netegrity/webagent/nete_wa_env.sh</em></pre><br/>Please note, that this shell level export won't be killed normally. Hence chance of accumulating such process is high.<br/><pre>ps -ef | grep LLAWP</pre><br/>to find any zombie processes which are being run and kill them off if you encounter below error...<br/><pre><br/> (67)Address already in use: make_sock: could not bind to address [::]:443<br/> (67)Address already in use: make_sock: could not bind to address 0.0.0.0:443<br/> no listening sockets available, shutting down</pre><br/>So kill the identified process and restart again.<br/><pre>kill -9 &lt;processid&gt;<br/>apachectl -k stop<br/>apachectl -k start</pre><br/>Issues you might encounter: Not able to shutdown LLAWP process which prevents Apache to restart<br/><br/>If I try shutting down<br/><pre># LLAWP /opt/apacheinstallation/apache/conf/WebAgent.conf -APACHE20 -shutdown<br/> [01/May/2012:11:27:59] [Info] [CA WebAgent IPC] [20906050] [CSmSem::getSem] Attempted to attach to non-existent semaphore with key 0xf4a818d7<br/> [01/May/2012:11:27:59] [Error] [CA WebAgent IPC] [20906050] [CSmIpcEvent::CSmIpcEvent] Error initializing semaphore -1<br/> [01/May/2012:11:27:59] [Error] [CA WebAgent IPC] [20906050] [CSmSem::GetValue] Error performing GETVAL operation on semaphore -1 - Invalid argument (22)<br/> [01/May/2012:11:27:59] [Info] [CA WebAgent IPC] [20906050] [CSmSem::getSem] Attempted to attach to non-existent semaphore with key 0xf4a818d7<br/> [01/May/2012:11:27:59] [Error] [CA WebAgent IPC] [20906050] [CSmIpcEvent::SetEvent] Error reinitializing event with key base 0x1f4<br/> [01/May/2012:11:27:59] [Error] [CA WebAgent LLAWP] [20906050] [Failed to send shutdown signal to the LLAWP. Ensure that the process is running and the path to the WebAgent.conf is correct.]<br/> The process was running at the time of above shutdown command.</pre><br/>The only workaround I was able to do is to<br/>1. Kill the LLAWP process    # kill -KILL $pidofLLAWP<br/>2. Remove all the shared memory and semaphores from the system<br/><pre># Bit dangerous: kill shared memory of LLAWP<br/> ipcs -m | awk ' $5 == "nobody" {print $2}' | awk '{ print $1}' | while read sharedMemory; do<br/> sudo su - -c "ipcrm -m $sharedMemory"<br/> done</pre><br/><pre># To kill all the semaphores<br/> ipcs -s | awk ' $5 == "nobody" {print $2}' | awk '{ print $1}' | while read semaphore; do<br/> sudo su - -c "ipcrm -s $semaphore"<br/> done</pre><br/>Update:<br/><br/><span>Found a solution for above Problem.</span><br/><br/><!--Ads1--><br/><br/><br/><span>Create another directory say "some_New_directory" within the "&lt;apache_installation_dir&gt;" and specify this as the "ServerPath" in WebAgent.conf</span><br/><pre>ServerPath=&lt;apache_installation_dir&gt;/&lt;some_New_directory&gt;</pre><br/>&nbsp;
